| ファイル | 役割 |
|---|---|
| `sanpai_notify.gs` | 赤（先生のご縁）の行事がある日の **12:05** に、参詣予定／参詣の入力状況をメール・LINE で通知する |

`matrix_from_calendar.gs`（カレンダー → マトリックス表の生成）はスキル
`kizuna-meeting-schedule` の assets 側にある。同じ Apps Script プロジェクトに

で始めて名前の衝突を避けている。

## sanpai_notify.gs

### なにをするか

1. 毎日 1 時台に走る巡回トリガーが、その日のシート（例 `令和8年.9月`）を読む
2. 6 行目の日付が「今日」で、7 行目の背景が**赤系**の行事を探す
3. あればその日の **12:05 ちょうど**に単発トリガーを仕込む
4. 12:05 に、その行事の「参詣予定」「参詣」列を集計して通知する

「毎日◯時」の定期トリガーは 1 時間の幅を持つため、分単位で合わせたい場合は
単発トリガーを使う必要がある。この二段構えはそのため。

赤い行事が無い日はトリガーを作らないので、通知も走らない。

### 通知の中身

```
【参詣状況】9/13(日) 12:05 時点

■ 東京報恩講 （ビッグサイト）
　9/13(日) 終日

〈参詣予定〉 入力 18/24
　参加 15 / ご縁なし 2 / 係 1
　未入力 6名
　高木和人、白井大貴、渡邉千咲、…

〈参詣〉 入力 0/24
　未入力 24名
　…

https://docs.google.com/spreadsheets/d/…
```

- **対象者**は「その列にプルダウンが入っている行」で判定する。学徒以外が
  グレーで塗り潰されている行は母数に入らない。プルダウンが 1 つも無い列だけ、
  E 列（対象）が空でない行を対象とみなす。
- `参加` / `ご縁なし` / `○伝` 以外の値（`係` など）もそのまま件数に出る。
- 「参詣予定」「参詣」列を持たない赤い行事は、その行事の列（`参加者`）を集計する。

### 導入手順

1. スプレッドシートを開き、**拡張機能 → Apps Script**
2. 「＋ → スクリプト」で新しいファイルを作り、`sanpai_notify.gs` の中身を貼る
3. プロジェクトの設定でタイムゾーンが **(GMT+09:00) 日本標準時** になっていることを確認する
   （単発トリガーの 12:05 はこのタイムゾーンで解釈される）
4. 送信先を決める（下の「送信先の設定」）
5. 関数一覧から **`sanpaiSetup`** を選んで実行し、権限を承認する

これで登録は完了。止めたいときは **`sanpaiRemoveTriggers`** を実行する。

### メニューを出す場合（任意）

`matrix_from_calendar.gs` の `onOpen` に 1 行足すと、シートのメニューから
確認・テストができるようになる。

```js
function onOpen() {
  const ui = SpreadsheetApp.getUi();
  ui.createMenu('マトリックス作成')
    .addItem('カレンダーから表を生成', 'generateMatrixFromCalendar')
    .addItem('CSVをダウンロード', 'downloadCalendarCsv')
    .addToUi();
  sanpaiBuildMenu(ui);          // ← この 1 行
}
```

`onOpen` は 1 プロジェクトに 1 つしか置けないため、`sanpai_notify.gs` 側には
定義していない。

追加されるメニュー「参詣通知」:

| 項目 | 動き |
|---|---|
| 今日の通知内容を見る | 送らずに文面だけ表示 |
| 日付を指定して見る | 過去・未来の日で文面を確認（9/13 などで試せる） |
| 今すぐ送ってみる（テスト） | 実際に送信 |
| 通知を有効にする / 止める | `sanpaiSetup` / `sanpaiRemoveTriggers` |

### 送信先の設定

**プロジェクトの設定 → スクリプト プロパティ** に入れる。

| キー | 値 | 既定 |
|---|---|---|
| `SANPAI_CHANNEL` | `email` / `line` / `both` | `email` |
| `SANPAI_EMAIL_TO` | 宛先アドレス。カンマ区切りで複数可 | 実行者本人 |
| `SANPAI_LINE_TOKEN` | LINE Messaging API のチャネルアクセストークン（長期） | — |
| `SANPAI_LINE_TO` | 送信先 ID（`userId` / `groupId` / `roomId`） | — |
| `SANPAI_REQUIRE_SANPAI_COLUMNS` | `true` にすると「参詣予定／参詣」列を持つ行事だけに絞る | 未設定（赤い行事すべて） |

何も設定しなければ、スクリプトを実行した Google アカウント宛にメールが飛ぶ。
まずこの状態で数日動かして、文面が期待どおりか見るのがよい。

#### LINE を使う場合

LINE Notify は 2025 年 3 月に終了したため、**Messaging API の push** を使う。

1. [LINE Developers](https://developers.line.biz/) で Messaging API チャネルを作る
2. **チャネルアクセストークン（長期）** を発行して `SANPAI_LINE_TOKEN` に入れる
3. 送信先の ID を `SANPAI_LINE_TO` に入れる
   - 自分宛: チャネルの Bot を友だち追加し、Webhook で届く `userId`
   - グループ宛: Bot をグループに招待して得られる `groupId`
4. `SANPAI_CHANNEL` を `line`（メールも欲しければ `both`）にする

push は無料枠に上限があるが、月数件のこの用途では問題にならない。

### つまずきやすい点

- **タイムゾーン**: プロジェクトが日本標準時でないと 12:05 がずれる。
- **シート名**: 対象月のシートは `令和8年.9月` の形で探す。名前を変えると見つからない
  （`令和8年.9月(1)` のような枝番は拾う）。
- **赤の判定**: 7 行目の背景色で見ている。生成スクリプトの赤は `#F8CECC`。
  手で色を変えるときは、赤・橙系（R が G, B より 25 以上大きい色）を保つこと。
- **見出し行**: `参加者` / `参詣予定` / `参詣` / `参加/ご縁なし…` のいずれかが
  最初に現れる行を見出し行とみなし、その 4 つ上を日付行として読む。
  行構成（6=日付, 7=会合名, 8=講師, 9=任責, 10=見出し）を崩さないこと。
- **通知は行事当日**。前日に催促したい場合は `sanpaiScheduleToday` の
  `sanpaiBuildReport_(now)` に渡す日付を翌日にずらす。
